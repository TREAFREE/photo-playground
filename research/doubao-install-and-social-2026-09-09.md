# 图片 Skill、豆包安装与图文表达：复查

## 先修正测试结论

此前在 `com.bot.neotix.doubao` 内打开的是 `doubao.com/chat/` 普通聊天界面。它没有成功读取第三方 GitHub 文件，但这不足以判断“豆包工作”的安装能力。这里将官方能力、他人实操和本机测试分开记录。

1. [豆包官方：工作任务模式有什么用](https://www.doubao.com/im-linkchat/help.html#/detail/23675)：本次在官方帮助界面直接读取，明确支持本地电脑、浏览器、Skills 与专业图片视频设计。
2. [豆包工作官网](https://www.doubao.com/work)：本次实际打开，提供独立客户端；不能把普通聊天页作为它的等价测试环境。
3. [BibiGPT 作者的对话安装实操](https://www.bibigpt.co/blog/posts/doubao-work-review-guide)：2026-08-26 的操作记录给出了“技能·连接器·伙伴 → 新建 → 与豆包对话新建技能 → 提供 GitHub 地址”的路径。它验证的是该作者的技能，并非本仓库。
4. [抖音公开教程合集页](https://www.douyin.com/shipin/7623588842209069071)：包含创作者对“工作任务 Turbo”“新工作任务”“本地电脑”和上传自定义技能的演示文稿。这与用户截图中的说法一致，入口名称随版本变化；不能从文稿推断每个账号都具备同样入口。

因此，“能让豆包下载 GitHub Skill 后调用”有可核查的实操依据；关键在具备安装和工具能力的工作环境。我们本机完成的是普通聊天正文生图，尚未完成豆包工作里本仓库的安装、重开任务调用与成图验证。此次没有安装另一个客户端或购买订阅。

| 本仓库 | 每款独立目录，规则、引用、版本和 ZIP 隔离；新款可用单文件表达 | 没有硬编码 OpenAI API；使用宿主现有参考图编辑工具。结构具备迁移条件，不等于已完成豆包工作全量测试 |

不是每个 Skill 都需要 Python 或 API。只表达审美与工作流程的 Skill，可由不同图像宿主解释执行；自带脚本或指定 API 的 Skill，还需要相应运行时、依赖和授权。安装成功、读取完整和最终好看是三个分别需要检查的环节。

## 图文参考与采用方式

- [抖音：普通照片变杂志插画的三步教程](https://www.douyin.com/video/7671263334334729482)：先展示照片变化，再给项目名和短步骤。我们采用“效果在前，操作在后”，不复用原文口号。
- 上述抖音教程合集的创作者文稿常把模式选择说得很快；我们的末页和正文明确标出工作任务入口。
- 小红书参考为用户此前提供的猫狗海报、照片手绘与拼豆截图：主体大、对照清楚、文字少、用个人感受引出收藏欲。本次小红书本机应用未成功打开，网页搜索未取得可核验的直接笔记全文；没有虚构小红书阅读、点赞或转化数据。

首组采用一张公开授权猫照片的四种玩法，抖音侧重悬赏令笑点，小红书侧重收藏与日常纪念。封面为独立 AI 排版设计；内页效果图直接复制既有样例文件，不重新生成或美化后冒充测试结果。两平台各备标题、正文、评论回复和七张有序图片。

用词约束：可说“免费开源”“已经整理成独立 Skill”“本组 Codex 生成”；不说“任何豆包都能一键安装”“免费无限生图”“零翻车”“必爆”“朋友圈刷屏”。拼豆称效果图，不称可照做的逐格图纸；不把图库照片称作自己养的猫。
