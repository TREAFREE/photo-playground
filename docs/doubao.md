# 豆包怎么使用这些规则

**复查更新：GitHub Skill 的对话安装有公开实操依据，应使用具备技能安装能力的豆包工作／工作任务环境。此前普通聊天测试不能代表工作模式。** [来源与源码对比](../research/doubao-install-and-social-2026-09-09.md)。

2026-09-09，在 macOS 豆包应用（`com.bot.neotix.doubao`）中实际测试。客户端打开的是豆包聊天界面；测试包含“深度思考”开关及图片生成界面，后者显示 Seedream 4.5。未找到并验证截图所说的“工作任务 Turbo”安装流程，不能推断其他账号或版本也一样。

## 在豆包工作中尝试安装

官方确认工作模式支持 Skills；公开实操使用“技能·连接器·伙伴 → 新建 → 与豆包对话新建技能”。某些版本显示“新工作任务”或“工作任务 Turbo”。先确认自己处于支持技能安装的工作环境。

可发送以下针对本仓库的安装请求（本仓库在豆包工作中的安装尚待实测）：

```text
新建技能。请从 https://github.com/TREAFREE/photo-playground
安装 skills/pirate-bounty-poster 这一款 Skill。
保留完整目录与它引用的资源；不要只总结 README。
安装后告诉我技能名称，并确认它出现在可调用的技能列表里。
```

如果你的工作界面支持“上传技能”，也可选择 Releases 中这一款独立 ZIP；具体上传格式以客户端提示为准。安装后新开工作任务，选中该技能，附图要求生成悬赏令。不要自己猜一个 `~/.doubao/skills` 目录。

本机目前验证的是下面普通聊天路径，并非上述工作模式安装。

## 可以照着做的办法

1. 在首页选一个风格，打开它的“规则”链接。先尝试只处理一张照片。
2. 上传照片，复制该 `SKILL.md` 正文到消息。如果正文引用了 `references/...`，同时提供对应文件内容；只看 README 会漏掉细节。
3. 在规则前加这句话：

```text
请按下面完整规则直接处理我附上的照片，生成一张成品图。
不要只解释风格，不要声称已安装 Skill。没有图片生成能力时请明确告诉我。
标题用我指定的文字；其他规则如下：
```

4. 检查结果：主体仍像原照片吗？文字正确吗？是否遵守留白和材质？指出最主要的一个问题再改一次。

新款 [建筑版画](../skills/architectural-relief-poster/SKILL.md) 和 [实景渐绘](../skills/scene-sketch-collage/SKILL.md) 都是自包含规则。上述正文粘贴方式已用建筑版画测试；上传 Markdown 文件、跨对话持久保存、`@Skill` 自动调用与其他款式仍需各自验证。

若你的豆包版本提供工作任务、联网读取和安装能力，可以尝试让它读取确切 Skill 文件及引用资源。但应检查真实读取记录和安装位置；模型回答“已经学会”不能作为安装证据。
